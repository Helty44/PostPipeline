# PostPipeline 🚀

PostPipeline — учебный проект на Python для конкурентной загрузки, обработки и сохранения постов из открытого API.

Проект демонстрирует три подхода к конкурентности: `asyncio`, `multiprocessing` и `threading`.

## Возможности

- Асинхронная загрузка 100 постов из JSONPlaceholder.
- Ограничение одновременных HTTP-запросов с помощью `asyncio.Semaphore(5)`.
- Обработка сетевых ошибок и таймаутов.
- Параллельный CPU-bound анализ постов.
- Расчёт индекса сложности и SHA-256 хеша.
- Межпроцессный счётчик и отдельный процесс мониторинга.
- Многопоточное сохранение результатов в `results.log`.
- Мониторинг прогресса и итоговый отчёт.

## Установка и запуск

Для запуска необходим Python и доступ к интернету.

1. Клонировать репозиторий.
2. Создать виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

3. Установить зависимости:

```bash
pip install -r requirements.txt
```

4. Запустить проект:

```bash
python main.py
```

После завершения работы создаётся файл `results.log` с результатами анализа постов.

## Architecture Choices

### 1. Asyncio — I/O-bound

Для загрузки постов используется `aiohttp` совместно с `asyncio`.

Асинхронный подход позволяет выполнять несколько сетевых запросов конкурентно, не блокируя основной поток во время ожидания HTTP-ответов.

`asyncio.Semaphore(5)` ограничивает число одновременно выполняемых запросов.

### 2. Multiprocessing — CPU-bound

Для математических вычислений используется `ProcessPoolExecutor`.

Отдельные процессы позволяют распределить CPU-bound вычисления между несколькими ядрами процессора.

Для синхронизации применяются `multiprocessing.Value` и `multiprocessing.Lock`.

Отдельный процесс получает ID обработанных постов через `multiprocessing.Queue`.

### 3. Threading — File I/O

Для сохранения результатов используется `ThreadPoolExecutor` с тремя рабочими потоками.

`queue.Queue` распределяет посты между потоками, а `threading.Lock` защищает запись в общий файл.

`threading.Event` используется для корректного завершения фонового потока мониторинга.

## Обработка ошибок

При сетевых сбоях загрузчик возвращает `None`, поэтому неудачные запросы исключаются из дальнейшей обработки.

Ошибки файловых операций и некорректные данные отдельных постов обрабатываются внутри потоков сохранения.

## Результаты тестирования

При одном из успешных запусков получены следующие результаты:

- Запрошено постов: 100
- Успешно загружено: 100
- Успешно обработано: 100
- Успешно сохранено: 100
- Общее время: 6,12 секунды

Время выполнения зависит от сетевого соединения и производительности компьютера.
